# Thesis Dataset Audit

## 1. Executive summary

This audit covers the five thesis synthetic datasets `er_n100_p005`, `sbm_n100_4c`, `ba_n100_m3`, `ws_n100_k8_p01`, and `expdeg_n100_lin`.

Verified from the repository:

- The final experiment configurations consume `datasets/<dataset>/CommunityGraphs_train.pkl` and `datasets/<dataset>/CommunityGraphs_test.pkl`.
- Each dataset contains 300 persisted graphs, split into 240 training graphs and 60 test graphs.
- Every persisted graph has exactly 100 nodes.
- The persisted graph format is `list[scipy.sparse.csr_matrix]`; all checked matrices are square, symmetric, binary, and diagonal-zero.
- The original train/test split is separate from the later OGAD validation split. In final runs, the 240 training graphs are further split into 192 model-training graphs and 48 validation graphs.
- The repository documents that all five datasets use `n=100`, but it does not document why the value 100 was chosen. It is safe only to infer that equal `n` controls graph size across families.
- The `expdeg_n100_lin` name suggests a linear profile, but the actual generator call does not persist or pass linear weights. The implementation samples weights uniformly from `[1, 20]` when no explicit `weights` parameter is supplied.

The SBM probability matrix is:

```text
[[0.10, 0.01, 0.01, 0.01],
 [0.01, 0.10, 0.01, 0.01],
 [0.01, 0.01, 0.10, 0.01],
 [0.01, 0.01, 0.01, 0.10]]
```

Generation details common to all five datasets:

- `generate_dataset` derives split, size, and per-instance seeds from the master seed with `derive_seed_plan`; see `community_graphs/seeds.py:6-15`.
- Each graph uses an attempt seed derived as `SeedSequence([instance_seed, attempts])`; see `community_graphs/generation.py:94-111`.
- Graphs are post-processed to remove self-loops when configured, relabel nodes consecutively, and convert to CSR adjacency; see `community_graphs/generation.py:66-83` and `community_graphs/csr.py:15-36`.
- CSR validation enforces square matrices, sorted CSR indices, binary values when expected, symmetry when expected, and no self-loops when expected; see `community_graphs/csr.py:64-107`.

The actual metadata records NetworkX 3.4.2 as the generation version for all five datasets, for example `datasets/er_n100_p005/metadata.json:411-415`. The repository wrapper is the primary evidence for parameter values; NetworkX source documentation gives the semantics of the external generator functions.

### Per-dataset mechanism

ER: `nx.gnp_random_graph(100, 0.05, directed=False)` chooses each possible undirected edge independently with probability `p=0.05`. Self-loops are not generated by the undirected pair iteration, and the repository config also disallows self-loops.

SBM: `nx.stochastic_block_model` uses four fixed blocks of 25 nodes. For every unordered node pair, the edge probability is selected from the block matrix above. Block assignments are fixed by the consecutive block sizes, not sampled.

BA: `nx.barabasi_albert_graph(100, 3)` starts from the default NetworkX initial graph when `initial_graph=None`, a star graph on `m+1=4` nodes, and then adds each new node with `m=3` preferentially attached edges. This yields exactly `3 + (100 - 4) * 3 = 291` edges per graph.

WS: `nx.watts_strogatz_graph(100, 8, 0.1)` starts from a ring where each node is joined to `k=8` nearest neighbors, then rewires each edge with probability `0.1`. The NetworkX implementation rewires rather than adding edges, so the number of edges remains `100*8/2 = 400`.

EDG: The repository does not pass explicit `weights`. Therefore `_expected_degree` uses `np.random.default_rng(seed).uniform(min_weight, max_weight, n)` with `min_weight=1`, `max_weight=20`, and `n=100`, then calls `nx.expected_degree_graph(weights, selfloops=False, seed=seed)`. NetworkX assigns edge probabilities of the form

```text
p_ij = min(w_i * w_j / sum_k w_k, 1)
```

for `i != j`, with no self-loops. Reconstructing all persisted generation seeds found no clipped pair probabilities. The maximum reconstructed pair probability was approximately 0.42876136 on the test split.

## 6. Why n=100?

Explicitly documented:

- The actual dataset configs set `"nodes": 100` for all five datasets.
- The reproducible suite script calls all five `gen` commands with `--nodes 100`.
- The generated README template says the suite uses `n=100`.

Not documented:

- The repository does not explain why the value 100 was chosen.
- It does not provide a thesis rationale such as computational cost, graphon resolution, comparability, or prior-work convention.

Reasonable inference:

- Because all five datasets use the same fixed `n=100`, graph size is experimentally controlled across graph families. This is an inference from the configs and persisted data, not an explicitly documented motivation.

## 8. Unknowns / ambiguities

- The repository does not explain why exactly `n=100` was chosen.
- The name `expdeg_n100_lin` is not enough evidence for a linear expected-degree profile. The actual code/config evidence shows random uniform weights from `min_weight=1` to `max_weight=20`, unless explicit `weights` are supplied; no explicit weights are supplied in the persisted config.
- The generated README comments call EDG a smooth rank-1 graphon case, but the exact per-graph weights are not stored in the metadata. They can be reconstructed from seeds and code, but they are not persisted as a simple table.
- A top-level README example for SBM shows an older/example `--nodes 200` and `sizes=[50,50,50,50]`; this is not the actual thesis dataset, whose metadata and suite script use `--nodes 100` and `sizes=[25,25,25,25]`.

### Safe statements for the thesis

The experiments use five synthetic graph datasets generated by the repository's CommunityGraphs pipeline: Erdos-Renyi, stochastic block model, Barabasi-Albert, Watts-Strogatz, and expected-degree graphs.

Each dataset contains 300 simple undirected graphs represented as binary symmetric CSR adjacency matrices, with 240 graphs in the training split and 60 graphs in the test split.

All persisted graphs in these five datasets have exactly 100 nodes.

The Erdos-Renyi dataset uses `G(n=100,p=0.05)`. The SBM dataset uses four fixed communities of 25 nodes with within-community edge probability 0.10 and between-community edge probability 0.01. The Barabasi-Albert dataset uses `n=100` and `m=3`. The Watts-Strogatz dataset uses `n=100`, `k=8`, and rewiring probability 0.1. The expected-degree dataset uses `n=100` and node weights sampled uniformly between 1 and 20, with edge probabilities proportional to the product of node weights and no self-loops.

Using the training split only, the empirical mean graph densities are 0.049913 for ER, 0.031775 for SBM, 0.058788 for BA, 0.080808 for WS, and 0.105096 for EDG.

The repository documents `n=100` as a fixed experimental parameter for the five datasets, but it does not document the reason for choosing the value 100.
